scan Escanear um diretório
1

Inicie a CLI

python3 hav_sentinel_launcher.py --cli
2

Execute o scan apontando para o diretório do projeto

sentinel $ scan ~/meu-projeto
3

Aguarde o processamento. O terminal exibirá o progresso em tempo real e as vulnerabilidades encontradas

[SCAN] Iniciando análise de /home/user/meu-projeto
[*] Processando: models.py
[*] Processando: config.py
┌─[VULNERABILITY: CRITICAL]──────────────
│ Title: SQL Injection Risk
│ Target: models.py
└────────────────────────────────────────

[+] Análise concluída: 15 problemas encontrados
Dica: use caminho absoluto (~/projeto ou /home/user/projeto) para evitar erros de diretório relativo.
scan Escanear subdiretório específico
1

Para escanear apenas uma pasta dentro do projeto, use o caminho completo até ela

sentinel $ scan ~/meu-projeto/app/controllers
2

Útil em projetos grandes para acelerar a análise de uma parte específica

scan Erros comuns no scan
Erro: caminho não existe
[-] Caminho não existe: /home/user/errado

Verifique o caminho com ls ~/ antes de executar o scan.

Erro: caminho com espaços
sentinel $ scan "/home/user/meu projeto"   ← correto
sentinel $ scan /home/user/meu projeto    ← errado
analyze Analisar arquivo Python
1

Informe o caminho completo até o arquivo

sentinel $ analyze ~/projeto/app/models.py
2

O resultado lista cada vulnerabilidade encontrada no arquivo

[*] Analisando: models.py

Vulnerabilidades encontradas:

1. [HIGH] SQL Injection — models.py
CVE: CVE-2023-XXXXX

2. [MEDIUM] Missing Input Validation — models.py

[+] 2 vulnerabilidades encontradas
analyze Analisar arquivo .env ou config
1
sentinel $ analyze ~/projeto/config/settings.py
sentinel $ analyze ~/projeto/.env
2

Detecta principalmente secrets hardcoded, debug ativado e conexões inseguras

┌─[VULNERABILITY: CRITICAL]
│ Title: Hardcoded Secrets
│ File: settings.py
│ Desc: API_KEY exposto em plain text
└──────────────────────────
analyze Analisar requirements.txt
1
sentinel $ analyze ~/projeto/requirements.txt
2

Verifica se algum pacote listado possui CVEs conhecidas

Pacotes vulneráveis encontrados:

● django==2.0.0 → CVE-2019-XXXX [HIGH]
Recomendação: atualize para django>=3.0.0

● requests==2.20.0 → CVE-2018-XXXX [MEDIUM]
Recomendação: atualize para requests>=2.28.0
report html Gerar relatório HTML visual
1

Execute um scan antes de gerar relatório

sentinel $ scan ~/projeto
2

Gere o relatório HTML

sentinel $ report html
3

O caminho do arquivo é exibido. Abra no navegador

[+] Relatório HTML gerado:
~/hav_reports/report_20260525_143022.html
4

Para abrir no navegador diretamente:

open ~/hav_reports/report_20260525_143022.html      # macOS
xdg-open ~/hav_reports/report_20260525_143022.html  # Linux
O relatório HTML contém: dashboard visual, estatísticas por severidade, tabela de vulnerabilidades e recomendações de remediação.
report json Gerar relatório JSON para integração
1
sentinel $ report json
2

O arquivo JSON estruturado fica salvo em ~/hav_reports/

{ "tool": "H.A.V. SENTINEL",
"summary": { "critical": 2, "high": 5 },
"findings": [ ... ] }
Use JSON para integrar com CI/CD, scripts bash, ou dashboards externos.
report Gerar ambos os formatos
1

Sem parâmetro, gera JSON e HTML ao mesmo tempo

sentinel $ report
[+] Relatório JSON gerado: ~/hav_reports/report_*.json
[+] Relatório HTML gerado: ~/hav_reports/report_*.html
vulndb list Listar todas as vulnerabilidades
1
sentinel $ vulndb list
2

O banco exibe tipo, CVE, severidade e como corrigir

● SQL_INJECTION — CRITICAL — CVE-2023-XXXXX
Remediação: Use prepared statements

● XSS — HIGH — CVE-2023-XXXXX
Remediação: Validate and encode output

● WEAK_AUTH — HIGH — CWE-521
Remediação: Implement MFA, OAuth2

● MISSING_VALIDATION — MEDIUM — CWE-20
Remediação: Comprehensive input validation
vulndb search Buscar vulnerabilidade específica
1

Informe o termo de busca após search

sentinel $ vulndb search XSS
sentinel $ vulndb search INJECTION
sentinel $ vulndb search SECRET
2

Retorna apenas as entradas que contêm o termo no nome ou na remediação

Buscando: XSS

● XSS — HIGH
CVE: CVE-2023-XXXXX
Remediação: Implement proper input validation and output encoding
Dica: use o resultado de um scan para buscar informações de remediação. Ex.: scan encontrou HARDCODED_SECRETS? Execute vulndb search SECRET.
network portscan Escanear portas de um servidor
1

Informe o IP ou domínio após portscan

sentinel $ network portscan 192.168.1.100
sentinel $ network portscan example.com
2

O sistema testa as portas mais comuns em paralelo (15–30 segundos)

[SCAN] Iniciando port scan em 192.168.1.100

✓ Porta 22 — ABERTA (SSH)
✓ Porta 80 — ABERTA (HTTP)
✓ Porta 443 — ABERTA (HTTPS)
✗ Porta 3306 — FECHADA (MySQL)
✗ Porta 5432 — FECHADA (PostgreSQL)
✗ Porta 6379 — FECHADA (Redis)
Portas perigosas se abertas: 22 exposto na internet = risco de brute force SSH. 3306/5432/27017 abertos publicamente = banco de dados exposto, risco crítico.
network ssl Verificar certificado SSL/TLS
1

Porta padrão é 443. Para outra porta, informe como terceiro argumento

sentinel $ network ssl example.com
sentinel $ network ssl example.com 8443
2

Exibe status, subject e data de expiração

Certificado SSL/TLS:

Status: Válido
Subject: {'commonName': 'example.com'}
Válido até: May 25, 2027

— ou —

Status: Inválido
Erro: certificate has expired
Se expirado: os navegadores bloqueiam o acesso. Renove o certificado imediatamente com Let's Encrypt ou seu provedor.
